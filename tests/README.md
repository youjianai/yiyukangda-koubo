# 回归测试用例

改规则后跑一遍这些用例，确认核心约束没有被破坏。

## 目录结构

```
tests/
  README.md              ← 本文件
  case_01_桃树叶泡脚/
    input.txt            ← 原文案
    expected_checks.md   ← 期望输出需满足的检查项
```

## 使用方法

每次修改 SKILL.md 或脚本后，用这些用例做端到端验证：
1. 在对话中粘贴 `input.txt` 的文案
2. 观察 skill 输出是否满足 `expected_checks.md` 的检查项
3. 如果某项检查失败，排查是规则改动导致还是 bug
